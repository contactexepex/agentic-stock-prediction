# Cockpit design system (scheme v2, "modern admin light")

Shared look of every cockpit page: tokens, components, icons and the app shell. One light scheme. Since 2026-10-08
it follows the owner's direction for the design track: the look of modern admin templates (the owner pointed at
Pixinvent's Materialize with its semi-dark vertical menu and at Aurora) applied to a broker-style cockpit, with the
owner's own rules kept (NO red; YES green, darker when strong; never colour alone; Paper on every signal). A soft
light-grey page, white cards lifted by a faint shadow (no hairlines), one periwinkle-indigo accent, a dark navy
sidebar with labels, icon tiles on KPI cards, label badges (tint plus ink), pill tabs, gradient area charts,
generous spacing. The previous scheme ("terminal light", 2026-10-07: hairline cards, ticker tape, dense stat strips)
used the same token and class names; the earlier design round's built pages keep their inlined copy of it.
Living style guide: `styleguide.html` (built from `styleguide.template.html` by `python design/system/build_styleguide.py`;
screenshots `styleguide-1280-full.png`, `styleguide-390-full.png`, `styleguide-390-viewport.png`).

**Verdict (owner's rule):** NO is red (`--mb-verdict-no-*`); YES is green, darker for a strong signal
(`--mb-verdict-strong-*`) and lighter for an okay one (`--mb-verdict-ok-*`). Strong = forecaster confidence >= 0.75
or anchored probability >= 0.65. Components: `.mb-verdict.no | .yes-ok | .yes-strong`.

**Never colour alone.** Up/down/hit/miss always carry a glyph (arrow, tick, cross, or the sign on a number via
`.mb-delta`) and the word; provenance tags carry a texture (Back-test hatched, Mock dashed, derived dotted) besides
the colour. Text tones (green `#15803d`, red `#dc2626`, accent `#5a5ee6`) are AA on white; the vivid template tones
live on fills and tints with a dark ink on them.

## Chart colours
Series 1 is the accent `#5a5ee6` (rule strategies, ranges, bands at alpha .30 for the 50% band and .12 for the 80%
band); series 2 `#e07b00` (baselines, orange), series 3 `#0b8fa6` (AI, teal), series 4 `#d6338f` (pink). Area charts
fade `--mb-chart-N-fill` to transparent. The actual line is the ink; hit/miss dots use up/down. Gridlines
`surface-container-high`, axis labels muted, the future area `surface-container-low`.

## How a page uses it
1. Template: put `<!--@@SYSTEM_CSS@@-->` in `<head>` and `<!--@@ICONS@@-->` first in `<body>`; write page-local
   layout CSS after it, using only token names (`var(--md-sys-color-...)`, `var(--mb-color-...)`). No page-local
   colours. Icons: `<svg class="ms"><use href="#ms-check"/></svg>`.
2. Builder: `from system import inline_system` (with `design/system` on `sys.path`) and
   `html = inline_system(template_with_data)`. Output is one self-contained file: no CDN, no font, no request.
3. Shell: wrap the page in `.mb-app` with `.mb-sidebar` (brand, section label, `.mb-nav-item`s with
   `.mb-nav-label`, a `.mb-sidebar-foot`), a `.mb-scrim`, `.mb-topbar` (menu button, title, `.mb-search`, the
   India/US `.md-segmented.light`, an action button), `.mb-content > .mb-content-inner`, and `.mb-navbar` (phone).
   The sidebar shows labels from 1200 px, icons only from 600 px, and slides in as a drawer on phones (`.open`).
4. Check: `node design/system/check_page.js <page.html> <out-dir> <prefix> ['#chart svg']`.
5. Tooltips: `data-tip="..."` on any element plus the small script in `styleguide.template.html` /
   `design/mockups/01-home/template.html` (hover, focus, tap; Escape closes).

Typography is the system sans stack (Inter or Public Sans when installed, else the OS sans; no web font);
numbers in tables use `.md-numeric` (tabular figures). Cards have 12 px corners and the soft shadow; tiles inside a
card are `surface-container-low` panels with 10 px corners. Breakpoints: sidebar with labels from 1200 px, icon
rail from 600 px, drawer plus bottom bar below; pages keep their own content breakpoints. Phone gutter 16 px, no
horizontal page scroll.
