# B15, Company pages UI (Wave 4)

## Scope
The Next.js pages 03-company (`/{market}/stocks/{ticker}`, reading `/api/v1/markets/{m}/stocks/{t}`), its per-day
call history (`/{market}/stocks/{ticker}/lifecycle/{date}`, reading `.../stocks/{t}/lifecycle/{date}` plus the company
page) and 04-stock-strategies (`/{market}/stocks/{ticker}/strategies`, reading `.../stocks/{t}/strategies`), built
from the approved mockups (`design/mockups/03-company/`, `04-stock-strategies/`) on B12's endpoints inside B7's app
shell; the company page's watchlist actions use B14's `CommandDialog` (read-only import of
`web/app/(cockpit)/[market]/companies/_parts/command-dialog.tsx`, B7's decision) on B11's command routes. Branch `build/b15-company-ui`.

Pure logic with node tests (`npm test` covers `lib/**/tests`): `web/lib/company-pages/` `types.ts` (the payload fields

`tests/logic.test.ts`.
UI cases: `web/tests/ui/cases/company.mjs` (B7's harness). No shared file changed; no dependency added.

## Contract
No API or data change. Reads only `/api/v1` (B12's routes; windows are B12's: news 30 days / newest 50, events 60
days, bars 250 sessions, owner 2026-10-08). Writes only through B14's `CommandDialog` (intents amount, deactivate, reactivate; mounted per opening
with a new React key, so each opening has its own Idempotency-Key) on B11's `POST .../companies/preview` and
`.../companies/commands`; `onRecorded` adds a pending line (the summary the owner confirmed) until the next import. Delete is not offered here (the Companies page's typed confirmation, F8). Links: `lifecyclePath`,
`companyPath`, `stockStrategiesPath` of `lib/ui/routes.ts`; a strategy name on page 04 links to
`/{market}/strategy-lab#<id>`.

Differences from the mockups, all because the app has real routes or real data:
- No example-company picker (mockup only, said so in the mockup).
- The confirm dialog is the Companies page's (B14): the form, the server's own summary, then Confirm (the mockup
  recorded a local pending line).
- The watchlist card links the call history of the last 10 sessions (the read model keeps 30; the call-history page
  has Earlier / Later links through all 30). The session list is the session being predicted plus the company's
  stored bars before it.
- Company events are worded by type: results widen the ranges and block a new call within a day ("widens ranges");
  an ex-dividend date only centres the ranges lower by the dividend ("shifts ranges"; `companyEventEffect`). The
  windows read "60 days" (B12's), not the mockup's "8 weeks".
- The news card's help says "first seen in the last 30 days (the newest 50)" (B12's window), not "every stored story".
- Page 04's agreement bars draw the baseline segment, which the mockup's SVG drops (the mockup's `.b` rect class
  clashes with a shared rule; the list under the chart has the same numbers).
- The call-history page (no mockup) shows, for one session D, every prediction with its path (made, checks, settled
  net, notes), the head-to-head picks, every intraday check of those trades, their settlements with the "why" bars and
  the analyst's notes; an older day is the API's 404 with "the history keeps the last 30 sessions".
- The call history's Earlier / Later links are built from the company's stored bars (no market calendar in the
  payload); a missing bar can make the oldest link a day the read model no longer keeps, which then shows the API's
  404 with "the history keeps the last 30 sessions" (issue #298, accepted).
