## How to build a page
1. `page.tsx` stays a server component for its metadata and renders the page's client component:

   ```tsx
   // app/(cockpit)/[market]/watchlist/page.tsx
   import type { Metadata } from "next";
   import type { Market } from "../../../../lib/data/constants.ts";
   import { WatchlistPage } from "./_parts/watchlist-page.tsx";
   export const metadata: Metadata = { title: "Watchlist" };
   export default async function Page({ params }: { params: Promise<{ market: string }> }) {
     return <WatchlistPage market={(await params).market as Market} />;
   }
   ```
2. The client component (`"use client"`) reads its endpoint with `usePage` and renders the states with `PageState`:

   ```tsx
   const res = usePage<WatchlistPayload>(market, "watchlist");          // or (market, "stocks/{ticker}", {ticker})
   return <PageState result={res}>{(p) => (<>
     <PageHead page={p} title="Watchlist" subtitle={`${p.name} · as of the ${fmtDate(p.as_of, false)} close`} />
     <SignalsBand page={p} goLive={p.go_live} strategies={Object.keys(p.strategies).length} />
     ...cards...
     <PageFooter page={p} endpoint="watchlist" />
   </>)}</PageState>;
   ```
   Type the payload as `PageBase & { ...your fields }` (`lib/ui/types.ts` has the shared blocks).
3. Layout CSS of the page goes in a stylesheet next to the page (page stylesheets are global in Next.js, so scope every
   rule under a root class of your page, e.g. `.mb-watchlist`; shared component classes carry the `mb-` prefix) (`_parts/watchlist.css`, imported by the client
   component), with token names only (`var(--md-sys-color-...)`, `var(--mb-...)`); no page-local colours. The
   mockup's own page CSS is a good start; the shared rules are already global (`styles/page.css` is the mockups'
   `_shared/shell.css`, `styles/components.css` the design system).
4. Links between pages use `pagePath(market, key)`, `companyPath`, `stockStrategiesPath`, `lifecyclePath` with
   `next/link`; never hard-coded URLs.
5. Words and numbers: formatters in `lib/ui/format.ts` (dates, the market clock from `status.session.local_time`,
   signed numbers with a true minus, money in the market's locale); the spec constants and labels in
   `lib/ui/constants.ts` (go-live bar, 60-word limit, assistant limits, News rules, family / band / flag / status
   words). Ask B7 for a shared one rather than copying it.

## Charting choice
The approved mockups draw every chart as hand-made SVG on the chart tokens, so the app does the same with small React
components and no chart dependency: `charts/small.tsx` (`RangeBar`, `HorizonBars`, `AgreementBar`) and
`charts/line-chart.tsx` (`LineChart` line / area chart with nice ticks, gradient fills, a cursor and one focusable
hit column per x with every value in its tooltip; `ChartLegend`), on the pure arithmetic of `lib/ui/scales.ts`.
Candlesticks use TradingView Lightweight Charts 5.2.1, the file the static dashboard already vendors, copied
unchanged to `web/public/vendor/lightweight-charts-5.2.1/` (NOTICE with version, source, SHA-256 and SRI; LICENSE)
and loaded from the app's own origin with Subresource Integrity by `charts/candles.tsx` (`Candles`, price lines for
ranges, entries and targets). `lib/ui/vendor.ts` pins URL, SHA-256 and SRI; `lib/ui/tests/design-sync.test.ts`
checks the file against the pin, the NOTICE and the dashboard's copy. No package dependency was added.

## Design system in the app
`web/styles/tokens.css`, `components.css` and `page.css` are unchanged copies of `design/system/tokens.css`,
`design/system/components.css` and `design/mockups/_shared/shell.css`; `components/icons/sprite.generated.ts` is
`design/system/icons.svg` (licence beside it). `node tools/sync-design.mjs` rewrites them and `--check` reports
stale copies (also a node test). `styles/app.css` holds the app's own additions (skip link, states, chat slot,
shared cells, chart rules), tokens only. Nothing is loaded from another origin (also a node test and a harness
check).

## Data hooks (`web/lib/ui/`)
- `use-api.ts`: `usePage<P>(market, endpoint, params)` and `useApi<P>(url)` return `{state: loading | error | ready,
  envelope, problem, reload}`; an invalid ticker is a 404 problem without a request.
- `api-client.ts`: `readPage` (GET with `If-None-Match`, a 304 reuses the cached envelope; problems keep the API's
  `fallback_links`; status 0 = no answer); `EnvelopeCache` (per tab, 64 URLs, nothing persisted).
- `types.ts`: the shared blocks of contract 2.0 (`PageBase`, `StatusBlock`, `GoLive`, `StrategyEntry`,
  `CompanyRecord`, `AgreementRow`, `OpenTrade`, `TradeCheck`, `Envelope`, `Problem`).

## Tests
- Node (offline, `npm test`): `lib/ui/tests/*.test.ts` (formatters, routes, the API client, scales and sorting, the
  design copies and the vendored file). Page sessions put logic they can test without a browser in `.ts` files
  with tests under their own `tests/` folder (the `npm test` glob covers `lib/**/tests/**/*.test.ts`; a test beside a
  page needs a glob added to `package.json`, a request to B5).
- UI harness (`web/tests/ui/harness.mjs`, after `npm run build`): `node --no-warnings tests/ui/harness.mjs [--only
  <name>]` starts `next start`, answers every `/api/v1` read from a fixture (default: the page's mockup `data.json`
  for the market, wrapped as the endpoint's envelope; `tests/ui/fixtures.mjs`), and per case and width fails on
  console errors, page errors, any request leaving the app's origin, horizontal overflow, elements past the edge,
  missing texts or elements, a first Tab stop other than the skip link, and the case's own `check`. It writes
  `work/ui/<case>/app-<width>-full.png` and, where the mockup has a screenshot at that width,
  `compare-<width>.png` (mockup left, app right) for the review against the mockup. Uses the global Playwright 1.56.1
  and the preinstalled Chromium. Add a page's cases in `tests/ui/cases/<page>.mjs` (`export const cases = [...]`,
  format in `cases/shell.mjs`), at the mockup's widths (`design/mockups/<page>/shot-*-full.png`), including its
  empty and error states (`api` lets a case answer a read itself; `routes` answers same-origin routes outside
  `/api/v1`, e.g. `/api/assistant`). The company endpoint's fixture is the 03-company mockup's shared keys plus
  `pages[ticker]` (`companyPayload`), as B12 serves it.
  Fonts: the app self-hosts Inter (below), so text widths do not depend on the machine; every case checks that the
  self-hosted Inter loaded. `--fallback-fonts` blocks the font files and hides any installed Inter (the browser then
  uses the next installed face, e.g. DejaVu Sans) for a robustness run in which width findings (overflow, past the edge, wider than the wrapper) are advisory
  (marked WIDE) and every other finding still fails.

## Font
The design's first face, Inter, is self-hosted: Inter 5.2.8 (variable, upright; latin and latin-ext subsets, the
latter carrying ₹) from the npm package @fontsource-variable/inter, copied unchanged to
`web/public/fonts/inter-5.2.8/` with its NOTICE (source, tarball integrity, SHA-256) and the OFL licence; declared as
the family "Inter" in `web/styles/fonts.css` (tokens.css unchanged) and the latin file preloaded by the root layout.
Before this (2026-10-08) the app loaded no font, so devices without an installed Inter rendered a fallback face and
some tables were wider than the design. `lib/ui/vendor.ts` pins the files; the node test checks them.

## Page 12, Help (batch 2)
`web/app/(cockpit)/[market]/help/` (`page.tsx`, `_parts/help-page.tsx`, `_parts/help.css`): the mockup's text and
layout as React. There is no Help endpoint: the data values it shows are read from two existing endpoints and selected
as the mockup's build selects them (`web/lib/ui/help.ts`): from `strategies` (Strategy lab) the registry, the
reference strategy and its go-live row (scope strategy, accuracy view, forward basis, all horizons), from `companies`
the default amount and the first active company by ticker with its N+1 agreement. `lib/ui/tests/help.test.ts` checks
that this selection on the two mockups' payloads equals `design/mockups/12-help/data.json` for both markets. When a
read fails, the explanations still show and only the data parts say they are not available (case `help-data-down`).
Differences from the mockup, all because the app has real routes: the Company and Stock strategies tiles link to the
watchlist (both need a ticker) and say so, and in the Paper card those two page names are plain text with a tooltip
(no link); the News tile describes the built News page (the mockup's line "folded into
Home and Company in this design round" predates page 09); strategy names link to `/{market}/strategy-lab#<id>` (B16
may read the hash to open that strategy); the top bar keeps the shell's company search on every page.
