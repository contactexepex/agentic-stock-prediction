## Changes on this branch
- #47 CSV line endings:
  - `.gitattributes` adds `data/**/*.csv -text`, so git never converts the stored CRLF files.
  - The collect gate (`pipeline/validate/collect_checks.check_csv_line_endings`, via `check_files`) blocks with
    `CSV_LINE_ENDINGS` on any stored CSV of the stage's kinds that has a bare-LF line. This covers every stored file,
    not only today's.
  - `row_checks.csv_line_ending_problem` holds the check.
  - Rejected: `union_by_name=true` in `core/database.kind_source_sql`. On the stored prices it reads every file
    (19050 US rows) in 4.02 s instead of 0.15 s, and it changes the last digit of float sums.
  - Tests: `tests/test_csv_line_endings.py`.
  - A stored file can't be rewritten (data rule 1), so clearing a `CSV_LINE_ENDINGS` block is a human decision.
    Cosmetic issue #143 asks for a documented recovery.
- #51:
  - Item 3: `collectors/news_window.slice_days` asks only the Pacific days from the window's start through now
    (`GOOGLE_NEWS_DAY_TIMEZONE` in `constants/news.py`). It no longer asks the day before the window, or a UTC
    "today" that hasn't started in Pacific time.
  - Item 4: the pending window of `pipeline/news_pending.py` is now closed at `since` (`>=`). One collector run
    stamps all its items with one `first_seen_at`, so an item of the newest enriched item's run that the analyst
    skipped stays pending. Enriched ids are still filtered out.
- #45:
  - Item 4: `special_session_hours` in `config/markets/india.yaml` (2024-11-01 18:00-19:00 and 2025-10-21
    13:45-14:45 IST, from NSE's circulars). `core/calendar._session_edge_utc` uses these hours for a listed special
    session. Without hours, the regular hours apply.
  - Item 1: the golden harness gives its children one OpenMP/BLAS thread each (`OMP_NUM_THREADS`,
    `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` = 1 unless already set).
- #46 (and #51 item 2):
  - `news_pending.py` writes a `priority` (`watchlist` or `background`) on each line and lists the watchlist lines
    first.
  - The news gate warns with `ENRICH_TEMPLATED` (`config/validate.yaml` `news_templated`) when more than 30% of at
    least 20 watchlist records repeat another record's summary word for word. Measured on the stored runs: India
    2026-10-07 (the keyword-rule run) 0.67; US 2026-10-07 0.09 and 0.12.
  - `.claude/agents/news-analyst.md` (news-v12): read each watchlist item on its own. Background items may be scored
    in groups with one shared summary starting "Background:".
- #59: docs/SPEC.md F1.2 says how the baselines trade (null threshold, every `up` trades, no probability ranking: they
  are not in the head-to-head view). F8.2 names `lifecycle.loader.active_sectors(cfg)`.
- #25 item 2: a CI job `neo4j-engine` in `.github/workflows/tests.yml` runs
  `test_real_engine_full_then_idempotent_incremental` against a disposable `neo4j:5.26-community` service container.
  The step fails unless that test ran and passed.

8. routine/PROMPT.md step 12 (#51 item 1), after "If the push is rejected, `git pull --rebase origin main` and push
   again.", add: "If that rebase stops on a conflict in an append-only data file (a news-only light run appended to the
   same day file meanwhile), never keep both sides by hand: a plain union can store one news id twice, and
   `DUPLICATE_ID` then blocks later runs. For each conflicted `data/` file, write main's version unchanged
   (`git show origin/main:<path>`). Then append only this run's added lines whose `id` is not already in it. An item both runs
   collected with the same headline and outlet has one id (`news_tags.item_id`), so the run's enrichment and evidence
   still point at a stored row. Other same-link copies keep their own ids and are hidden on read (`news_id_map`). Then
   `git add` the file and `git rebase --continue`. Every kind a light run writes (news, news_runs, news_updates,
   news_articles, news_clusters, announcements) has an `id` column (checked in `core/schemas.py`). A conflict outside `data/`, or a second failed push: stop, and say so
   in the Slack draft's failures line."
