# B10: horizons N+1..N+5

## Scope
Wave 2, session B10 of docs/SPEC.md section 10 (F2.7, decision 37) on branch `build/b10-horizons`.

N+k means: buy at the open of D, the first market session after the as-of close; sell at the close of the k-th
session after D. Weekends and the market's holidays are skipped through the market calendar.

B10 extends the following to every horizon of `config/strategies.yaml` with that definition:
- the signal model (labels, panel, monthly refit per horizon, Platt calibration, walk-forward backtest per horizon
  after costs);
- `ranges.py` / `range_math`, calibration, call scoring and the prediction rules;
- the weekly review, the replays, and the report, dashboard and chart files that W1 assigned to B10.

Old records keep their window and get a label on read.

## Contract
- **Horizon list**: `marketbrief/core/horizons.py`:
  - `horizons()` and `ai_horizons()` read `config/strategies.yaml`. A scratch test config without that file falls
    back to the repository's own.
  - `exit_offset(k) = window_sessions(k) = k + 1`: the sessions from the as-of close to the exit close.
  - `entry_exit(cfg, as_of, k)` returns D and the exit session.
  - `legacy_label` and `horizon_key` give the label of an old row and the summary key of a horizon.
  - `config/ranges.yaml` has no `horizons:` any more. `load_ranges_config()` fills it from strategies.yaml (a test
    config may still pin its own list). The `HORIZONS` constants in `constants/model.py`,
    `constants/prediction_rules.py` and `constants/dashboard.py` are gone.
  - Adding N+10 is a config change plus a model refit. The one exception is `agent_reasoning`, which has
    `decision_1d` .. `decision_5d` columns only.
- **Labels**: `n_plus_k` (every row written from now on), `legacy_cc` and `legacy_5d_d4`.
  - New `model_scores` and `ranges` rows carry `horizon_label`, `entry_date` and `exit_date`.
  - `outcomes`, `calibration` and `model_versions` carry `horizon_label`.
  - Rows without a label are labelled on read: a B10 block at the end of `sql/views.sql` redefines
    `ranges_latest`, `model_scores_latest` and `track_record` with a filled `horizon_label`. The views that read
    them (`open_ranges`, `range_record`) pick it up.
  - Old ranges and close-to-close calls are `legacy_cc`.
  - Old open-to-close model scores and calls are N+1 (1-day, the same window) or `legacy_5d_d4` (5-day, D+4).
  - Pooling: calibration (live pool), ACI, the live ablation and `scores_asof` / `ranges_asof` use N+k rows only.
    `scoring.summary`, the context pack and the review key legacy rows apart (`1d legacy_cc`,
    `open_to_close legacy_5d_d4`), and the review's `all` holds N+k ranges only. Open-to-close 1-day rows count as
    N+1, the one pooling the spec allows.
- **Calls**: `config/settings.yaml` gets `call_scoring.n_plus_k_from` (2026-10-07T22:41:00+00:00, the time B10 reached main;
  owner decision).
  - An open-to-close 5-day call made before it is scored at D+4's close and stored as `legacy_5d_d4`.
  - Every other open-to-close call of horizon k is scored at the close of D+k.
  - Close-to-close calls (made before the switch) keep their h-bar window (`legacy_cc`).
  - Outcomes store `horizon_label`.
- **Prediction rules**: `horizon_days` may be any configured horizon (1-5). The message is
  `MSG_HORIZON_NOT_CONFIGURED`.
- **Signal model**: `model/labels.end_offset` is k + 1 for both conventions.
  - Close-to-close now runs from the as-of close to the same exit close.
  - The panel, refit, Platt calibration, backtest and news report loop over `horizons()`.
  - Model ids: N+1 keeps `<market>-1d-open_to_close-<version>-<cutoff>`, so its stored fits stay valid.
    N+2..N+5 use `<market>-<k>d-n_plus_k-...`, so the stored D+4 fits are never reused for N+5.
  - `agent_reasoning` gets optional `decision_2d`..`decision_4d` columns (absent = abstain). `decision_1d` and
    `decision_5d` stay required.
- **Ranges**: the target is the exit session (`target_date = exit_date`), and `entry_date` is D.
  - The width is sigma x sqrt(k + 1).
  - The calibration pool is z over k + 1 sessions.
  - Mid-session (D open): every horizon is published, noted late. Before B10, the 1-day range targeted D and was
    left out.
  - Late run: a horizon whose exit session has closed is skipped.
  - The range-input switches (`enabled: {us: [1]}`) keep their keys and now mean N+1.
- **Records for B2, B3 and B9**: `contracts/horizons.py` `horizons()`, `scores_asof(market, as_of, horizon_days)`
  and `ranges_asof(...)`, built in `analytics/horizon_records.py`.
  - `scores_asof`: the newest N+k score per ticker and horizon computed by `as_of`.
  - `ranges_asof`: the first N+k range per id of the newest as-of date made by `as_of`.
  - Neither looks ahead. Missing `entry_date`/`exit_date` (old N+1 scores) are filled from the calendar.

## Model variant for `cross_market` strategies (accepted request from B2)
B2 asked how a score with the cross-market groups on would be exposed: strategy `rule.model_news_global.v1` has
`cross_market: true`. Accepted, because the signal model is B10's and F2.1 makes cross-market groups a strategy
parameter.
- `model_scores.py` now writes two models per horizon each day:
  - **base**: config/model.yaml as written. It goes to `model_scores` / `model_versions`, unchanged. The forecaster
    anchors on it, and every existing reader reads it.
  - **cross_market**: every cross-market group of the market switched on. It goes to the new kinds
    `model_variant_scores` / `model_variant_versions`, with the same columns plus `model_variant` and ids ending in
    `-cross_market`.
- The variant is kept out of `model_scores` so that no reader of it (B2's signal_inputs and paper_follow, B9's
  intraday, the warehouse, the dashboard) ever sees two rows per ticker and horizon.
- Read the variant with `contracts.horizons.scores_asof(market, as_of, horizon_days, variant="cross_market")`. The
  default `variant="base"` keeps the old call unchanged. An unknown variant exits with a message.
- Base output is unchanged: a scratch run with the variant gave the same `prob_model` for every base row as before.
  The only differences were in the news term, from news data merged since.
- Daily run time on a scratch copy of data/ (`MB_NOW=2026-10-07T11:00:00+00:00`): `us exit 0 9.902842338s` and
  `india exit 0 10.142161220s`. Each wrote 182 new rows and 9 new model versions (4 base N+2..N+5 and 5
  cross_market N+1..N+5).
- B2's other points:
  - The fields B2 reads exist (note `center` is a log shift).
  - The walk-forward probabilities come from `model/walk_forward.walk_forward`. Wiring them into the lab is B2's job.
  - `predictions` has no `horizon_label`: B3's forecaster writes them; outcomes carry the label.
