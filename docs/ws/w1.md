# W1: data catalogue and record formats

## Scope
Wave 1 of docs/SPEC.md section 10 on branch `build/w1-catalogue`. W1 delivers:
- the data catalogue and its example files;
- the storage formats of the new kinds of SPEC section 4;
- `config/strategies.yaml`, `mcp/tools.yaml` and the interface stubs in `marketbrief/contracts/`;
- the file assignment list for the Wave 2 sessions.

No feature logic, API contract or page shape.

## Contract
- **Data kinds** (jsonl, `data/<market>/<kind>/YYYY/MM/YYYY-MM-DD.jsonl`, append-only). The column comments in
  the schema files hold the id formats and enums.
  - `core/schema_lab.py`: `strategy_predictions`, `strategy_abstentions`, `paper_trades_settled`,
    `head_to_head_picks`, `trade_reasons_ai`, `trade_checks`, `eod_analyses`, `research_reviews`, `news_impact`.
  - `core/schema_lifecycle.py`: `watchlist_events`, `command_log`.
  - Conventions:
    - `horizon_days` = k of N+k;
    - prices are raw, in the market currency;
    - `_pct` = percent points;
    - probabilities are 0-1.
  - No session writes these kinds yet; `connect()` exposes each one as an empty table until rows exist.
- **`config/strategies.yaml`**:
  - `version`, `horizons: [1, 2, 3, 4, 5]` and `ai_horizons: [1, 3, 5]`;
  - `reference`: the documented default parameter set;
  - `strategies`: 8 rule strategies, 3 baselines and 4 AI traders. Each entry has id, family, name,
    description, compared_to, differs_in, parameters, threshold, horizons and live_from (all `null` until
    Wave 5).

  The allowed values are in `marketbrief/contracts/strategies.py`, checked by `tests/test_w1_catalogue.py`
  (`strategy_problems`). Each rule strategy and baseline differs from its `compared_to` in exactly the one
  parameter `differs_in` names.
- **`mcp/tools.yaml`**: the 13 F10 tools. For each one it gives kind, inputs (with shared `common_inputs`),
  output entities and read models, per-channel permission, and for writes: idempotency key, confirm step,
  `writes`, validator, refusals. Delete is dashboard-only, with a typed confirmation.
- **Interfaces** (`marketbrief/contracts/`). A function raises `NotImplementedError` until it is built, then
  delegates. `watchlist` delegates to B1's `lifecycle/accessor.py`, `protocol` to B2's `lab/protocol.py`, and
  `horizons` still raises:
  - `protocol`: the F1 engine. It has `entry_session`, `exit_session`, `is_locked`, `qualifies`, `quantity`,
    `round_trip_costs`, `settle`, `strongest` and `pick`, plus the types `Costs` and `Candidate` and the enums
    (views, pick rules, statuses, flags, reason codes, abstention codes, check flags). Built by B2.
  - `watchlist`: `watchlist(market, as_of, state)`, `company`, `trade_amount` and the `Company` record. The
    state rules and the new loader key `active_tickers` are described there. Built by B1.
  - `horizons`: `HorizonScore` and `HorizonRange` = today's `model_scores` / `ranges` columns plus
    `horizon_label` (`n_plus_k`, `legacy_cc`, `legacy_5d_d4`), `entry_date` and `exit_date`. Also the
    functions `horizons()`, `scores_asof` and `ranges_asof`. Built by B10.
- **`api/openapi.yaml`**: unchanged. The payload shapes come from the approved mockups in Wave 3 (B4).

## File assignment list
Built from greps on branch `build/w1-catalogue` (working tree as of 2026-10-07). Line numbers are from `grep -n` on this checkout.

**Company-list greps.** I started from `grep -rlE "CFG_TICKERS|CFG_SECTORS|\[.tickers.\]|\[.sectors.\]|get\(.tickers.|get\(.sectors." scripts sql`, which returned 74 files. I then added the indirect helpers and their callers:
- `core/market_config.py` has no helper that returns a ticker list. The indirect readers are `core/database.py own_exchange_keys`, `sources/nse_parsing.py nse_symbols`, `sources/sec_filings.py watch_ciks` and `analytics/news_tags.py Tagger(cfg)`.
- Only the config's `tickers:` / `sectors:` lists count. A news row's `tickers`, `primary_tickers`, view or summary dicts and a symbol's own ETF `sectors` list do not count.

**Horizon greps.** I grepped for `HORIZONS|horizon|horizon_days|"1d"|"5d"|_1d|_5d|(1, 5)|[1, 5]|D+4|shift(-|1-day|5-day|=== 1|== 5|("1", "5")`. I left out indicator lookbacks, because they are features and not horizons: `ret_1d`, `ret_5d`, `bench_ret_5d`, `vol_change_1d`, `rel_sector_5d`, `cue_ret_1d`, `move_1d/5d`, `short_pct_5d`, the `momentum_1d/5d` baselines, Yahoo `interval="1d"` and Google News `when: 1d`.

**Classes.** collect = collecting, tagging, features or verification for every collected company. predict = calls, model scores, ranges, picks, trades, the forecaster's context pack, or gates on calls. display = report, dashboard, Slack, charts, warehouse, HTML, report gates.

**Files left out.** These belong to W1 itself and are not on the list: `core/schema_lab.py`, `core/schema_lifecycle.py`, `marketbrief/contracts/` and `config/strategies.yaml`. `constants/config_keys.py` only defines the key names (`CFG_TICKERS`, `CFG_SECTORS`); `graph/neo4j/shapes.py` 57 reads a row's tickers, not the config (both checked, no change).

**Config (non-script) owned by B10 per the spec.** `config/model.yaml` and `config/ranges.yaml` (`horizons: [1, 5]`) belong to B10.

**Shared files.** `sql/views.sql` stays a shared file under the additive rule (new blocks at the end): B9 changes the intraday view named below; any other session that needs a view appends a block. `core/schemas.py` and `constants/kinds.py` keep the one-import-and-one-spread-line and marked-block rules.

## Open questions
Each question has the default W1 took.

1. **Answered** (B2's F1.7.3 correction, owner decision on gain per session; see docs/ws/b2.md). Original
   question: **"Best expected gain" almost always picks the shortest horizon** (F1.7.3). `move` uses the target, which is
   the centre of the range, while `loss` uses the low end of the 80 % range (a tail). So
   `p × move − (1 − p) × loss − costs` is negative at every horizon unless p is very high, and it is most
   negative for long horizons. In the example data, every head-to-head candidate has an expected gain between
   -1.12 % and -2.78 %, and the gain pick is always N+1.
