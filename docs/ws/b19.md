Session B19, branch `build/b19-golive`. Job (docs/SPEC.md section 10, Wave 5, the last steps):

1. measure the pre-open run's duration;
2. run the whole day end to end for both markets;
3. switch on the new paper trading as a judged change;

## 1. What "switch on the new paper trading" means (found on main be7d5c7)

**The switch.** The switch is `live_from` on each of the 15 entries of `config/strategies.yaml`:

- 8 rule strategies, 3 baselines and 4 AI traders;
- all are `null` today;
- the file says "Wave 5 sets the first session when the new paper trading is switched on";
- `docs/DATA_CATALOGUE.md` defines it as "first session it trades for real".

An id's behaviour may not change after its `live_from` (rule in the file header; `traders/director.py` already refuses
config diffs that change a live strategy).

**Owner of the mechanism.** B2 owns the paper-trading engine (`marketbrief/lab/`, session_01ULk82fEzTJfJoq5wsJDAVF).
B19 owns only the config change that sets the dates. That change is judged.

**Gap found (sent to B2 and the orchestrator, 2026-10-08).** No code reads `live_from` for trading:

- `lab.py predict`, `pick` and `settle` (`settle_run.py`) trade every qualifying row;
- the scoreboard's `forward` basis is every settlement that is not a back-test (`scoreboard.py`);
- the open-trade readers also ignore it: B9 `intraday/`, B6 `alerts/` and B4's `rm_*`. Only `warehouse/rm_common.py`
  shows a `live` flag.
- The live daily runs of 2026-10-08 already stored AI-trader `strategy_predictions`:
  - India: 66 rows;
  - US: 62 rows (commit da6f538).

  Once `settle` is wired, these pre-go-live rows would settle as forward paper trades and count toward the go-live
  bar.

Proposal sent to B2:

- One shared check: "live on D" = `live_from` is set and `live_from <= D` (the entry session).
- It gates:
  - settlement: a non-live row settles nothing and appends nothing;
  - picks: a non-live strategy is no contender;
  - the scoreboard's forward basis: only D >= `live_from`;
  - the open-trade readers (B9, B6, B4).
- Pre-live rows stay stored, because `data/` is append-only, but never trade.

B19's switch-on depends on this being on main.

**What the first live day writes** (per market, once the switch is on and B17's schedules run):

| Run | Writes to `data/<market>/` | Slack |
|---|---|---|
| Pre-open (D) | `strategy_predictions`, `strategy_abstentions` (rule, baselines, 4 AI traders); `head_to_head_picks`; `cost_views` (prediction and pick rows) | morning picks (B6) |
| Intraday x2 | `trade_checks` for every open trade (from D's open), `intraday_checks`, `intraday_runs`, `intraday_alerts`, `intraday_explanations` | intraday alerts (B6) |
| Post-close (D) | `paper_trades_settled` and `cost_views` for N+1 trades **of the previous live day only**: the first live day has no due trade, since N+1 of D exits at the close of D+1; `trade_reasons_ai`, `eod_analyses` (empty day) | close results (no trades yet) |
| Post-close (D+1) | the first N+1 settlements; N+5 first settle on D+5 | close results |

## 3. Go-live checklist (switch-on day)

1. Confirm P1-P7.
2. Choose the go-live date G: the first session of **both** markets on or after the switch-on commit, with the
   commit pushed before India's pre-open run (07:40 IST) of G.
   - If the two markets have different holidays, each market's `live_from` is still G.
   - A market closed on G starts on its next session; "live on D" compares dates, so nothing else changes.
3. Judged change: set `live_from: G` on all 15 strategies in `config/strategies.yaml`. Record G in this file and in
   docs/SPEC.md (decision 23 row and section 10 Wave 5), and append the judge verdict to `judgments/log.jsonl`.
4. Self-merge to main and verify with `git branch -r --contains <sha>`. Send G to the orchestrator.
5. G pre-open: watch `work/steps/` summaries (traders add, `lab.py predict`, `pick`), the morning post, and check:
   - `strategy_predictions` with made_at < open of G;
   - first commit of those rows before the open.
6. G intraday: `trade_checks` rows exist for every open trade.
7. G+1 post-close: the first `paper_trades_settled` rows (N+1); `cost_views` your-cost rows; the close post.
8. G+5 post-close: the first N+5 settlements. Review date = G + 2 months (first formal review, decision 23).

## 4. End-to-end test plan (dry and local; nothing published, nothing pushed to `data/`)

### Isolation

- Every test runs in a throw-away clone under the session's scratchpad, made with `git clone` from this checkout.
  Its `origin` push URL is set to an invalid value, so no commit there can reach GitHub.
- All secrets are unset for each command:
  `env -u SLACK_BOT_TOKEN -u SLACK_WEBHOOK_URL -u MOTHERDUCK_TOKEN -u MOTHERDUCK_INBOX_TOKEN -u NEO4J_URI -u REVALIDATE_SECRET`.
  The container has them set, so this is required, not optional.
- Every publishing step also gets its dry flag:
  - `notify_slack.py --dry-run` and `alerts.py --dry-run`;
  - `warehouse_sync.py --local` (the config's local file under `work/`), or `--dry-run`;
  - `neo4j_sync.py --dry-run`.
- Any real Slack post or MotherDuck write needs the orchestrator's OK first; none is planned.

### The clock

- `MB_NOW` freezes each run at its scheduled time (ISO 8601 with offset).
- Collectors still fetch live data from the allowlisted HTTPS sources. The test day is therefore the real current or
  next session, run at its real schedule where possible. Otherwise the as-of runs (`MB_NOW`) use stored data only.

### Pre-open duration (job step 1)

- Run the pre-open prompt for India and the US in the clone, following B17's prompt literally, agents included.
- Record per step:
  - wall-clock start and end (`date -u` around each command, saved to `work/b19_timing_<market>.tsv`);
  - for the subagent steps: their duration.
- Report against the budget:
  - India: start 07:40 IST, open 09:15, so 95 min; trader cut-off 09:00.
  - US: start 07:45 New York, open 09:30, so 105 min; trader cut-off 09:15.
- Report the critical path (collect, features, model, news analyst, debate, forecaster, traders, `lab.py pick`) and
  the margin to the trader cut-off.

### Whole day (job step 2), per market, in order

| Run | Commands (from the routine prompts after B17) | Checks |
|---|---|---|
| Pre-open | `routine/PROMPT.md` all steps | gates pass or fail as documented; predictions, abstentions, picks and cost_views written in the clone; morning post in `work/alerts_dryrun/` |
| Intraday 1 and 2 | `routine/INTRADAY_PROMPT.md` at the two check times (`MB_NOW`) | trade_checks rows for every open trade; explainer gate; alerts feed and dry-run post |
| Post-close | `routine/POSTCLOSE_PROMPT.md` | settle summary (due, settled, refused, waiting); EOD gate; close and corrections dry-run posts |
| News | `routine/NEWS_PROMPT.md` once | news gate; `commit_paths` only news folders |
| Weekly | `routine/WEEKLY_PROMPT.md` on a dry Saturday (`MB_NOW` = Saturday 10:00 local) | news-impact rows; director gate; weekly dry-run post |
| Results | `routine/RESULTS_PROMPT.md` once (if B17 schedules it) | results gate |

- Settlement needs due trades. The clone gets a live-on-D test (`live_from` set to a past session in the clone only)
  so `settle` has stored predictions to settle. The clone's own earlier pre-open rows are used; nothing is invented.
- Every failure is listed with its command, exit code, the summary's error and the owning session. Each is sent to
  that owner as a request. B19 fixes only its own files.
