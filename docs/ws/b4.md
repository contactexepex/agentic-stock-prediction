## Contract

### Contract layout (api/)
- `api/openapi.yaml` (B4): shared parts and platform paths. `api/paths/<page>.yaml`: a map path -> path item.
  `api/schemas/<page>.yaml`: a map schema name -> schema. Every `$ref` is written against the bundled document
  (`#/components/schemas/X`). `marketbrief.warehouse.openapi_spec.bundle()` merges them; a name defined twice fails.
- Shared components a page reuses: `ReadModelMeta` (envelope), `PageHeader` (market, name, currency, as_of, and the
  serve-time cutoff and built_at), `HorizonChoice`, `StatusBlock`, `GoLive`, `StrategyEntry`/`StrategyMap`, `Market`,
  `Ticker`, `Horizon`, `IsoDate`, `IsoTime`, `NullableNumber`, `NewsStatus`, `LabelBasis`, `Problem`, the parameters
  `Market`, `Ticker`, `IdempotencyKey` and the responses `NotFound`, `Unavailable`, `NotImplemented`, `Conflict`,
  `Invalid`, `Unauthorized`.
- A read operation: `x-read-model: rm.<table>` (a registered builder's table), 200 = `allOf [ReadModelMeta,
  {payload: <PagePayload>}]`, plus 404 and 503. A write: an `Idempotency-Key` parameter.

### Read-model framework (scripts/marketbrief/warehouse/)
- A page module `rm_<page>.py` declares `BUILDERS = (PageBuilder(table, schema, build, owner=..., serve="page"),)`
  and `CONTRACT_CASES = (ContractCase(...),)`. The registry finds every `rm_*` module (no list to edit); a table built
  by two modules is an error.
- `build(ctx)` returns `{page_key: payload}`. `ctx` (`BuildContext`): `cfg`, `con` (the repo's DuckDB),
  `cutoff_time`/`cutoff` (the run's clock, MB_NOW-aware), `dashboard` (gather_dashboard as of the cut-off, computed
  once), `as_of`, `companies` / `collected` / `active` (B1's `watchlist(market, cutoff, "collected")`; deleted
  companies never appear), and `shared(name, compute)` (computed once per build).
- Shared blocks (`rm_common.py`, one per catalogue record every page repeats): `header`, `horizons`, `status_block`,
  `strategies(ctx, fields)`, `go_live`, `lab_summary` (B2's scoreboard, comparisons and heatmaps of the collected
  companies' settled trades as of the cut-off) and `settled_trades`.
- Rules: read rows stored at or before `ctx.cutoff` only; filter stored rows on `ctx.collected` (and `ctx.active`
  where the page shows active companies only); never put a build time into a payload.
- Serve modes: `page` (2.0 page payloads: the route adds `cutoff` and `built_at` at the top and `freshness` inside `status`),
  `status` (adds `freshness` at the top), `verbatim` (1.0). Freshness: stale after 480 minutes.
- The sync validates every payload against its schema before writing; an invalid page keeps its old row and fails the
  build (`invalid_pages`). After the commit a MotherDuck sync posts the changed and deleted keys to
  `/api/v1/internal/revalidate` (REVALIDATE_SECRET, VERCEL_AUTOMATION_BYPASS_SECRET; non-blocking, summary key
  `revalidate`).

### Web data layer (web/lib/data/)
- `definePage({table, serve})`, `readPage(request, spec, market, pageKey, deps)`, `readTickerPage(...)`,
  `defaultDeps()` (from `deps.ts`: MotherDuck behind the data cache). One keyed SELECT per request, tag
  `rm:<table>:<market>:<page_key>`, revalidate 86400 s; ETag = payload_sha256 (304), 404 Problem, 503 Problem with
  the static reports as fallback links (warehouse down, or a row of another major version).
- A route (copy of the status route):
  ```ts
  import { MARKET_PAGE_KEY } from "../../../../../../lib/data/constants.ts";
  import { defaultDeps } from "../../../../../../lib/data/deps.ts";
  import { readPage } from "../../../../../../lib/data/handler.ts";
  import { HOME_PAGE } from "../../../../../../lib/data/home.ts";   // definePage({ table: "home", serve: "page" })

  export const runtime = "nodejs";
  export const dynamic = "force-dynamic";

  export async function GET(request: Request, { params }: { params: Promise<{ market: string }> }) {
    return readPage(request, HOME_PAGE, (await params).market, MARKET_PAGE_KEY, defaultDeps());
  }
  ```
  Relative imports (the node test runner does not resolve `@/`); tests import `handler.ts`, never `deps.ts`.

### Contract tests
- `ContractCase(path, table, mockup, mockup_payload, map_paths=(), page_keys=None, extra_keys=())`: the endpoint, its
  table, the mockup's data.json and a function giving the mockup's payload of a built page; `map_paths` names objects
  keyed by data (e.g. `$.strategies`, `$.agreement`).
- `tests/test_api_contract.py` syncs both markets from the repo's stored data as of 2026-10-07T12:00Z and runs every
  registered case: the served response validates against the operation's 200 schema, and its payload matches the
  mockup in shape (every mockup key present, no key the mockup lacks, list items against the merged item shape, null
  matches any type). `scripts/api_contract.py --market M [--local]` runs the same check on the live warehouse.
- The node tests (`web/lib/data/tests/`) check the route helper with an in-memory store; `serve.fixture.json` keeps
  the Python and TypeScript serve rules equal.
