## Contract
- Routes (B7's table, `web/lib/ui/routes.ts`): `/{market}/strategy-lab` reads `strategies`, `/{market}/track-record`
  reads `track-record`; both through B7's `usePage` and `PageState` (loading, error with retry and fallback links).
- Strategy lab: the selected strategy follows the URL hash `#<strategy_id>` (B7's Help page and the portfolios page
  link it so); clicking a name writes the hash. The page opens on the payload's `default_horizon` (`all`), the
  accuracy view, the forward basis and market cost, as the mockup does.
- Forward and back-test rows are never pooled: every table, KPI, heatmap and line reads one basis; the cumulative
  lines and the week heatmaps exist for the forward basis only; the back-test basis shows the run's facts
  (`backtest_run`; a null `note` is left out).
- Rule vs AI reads `compare` for everything but the research review, which it reads from `review` (the handover's
  rm.review) with the review's own loading and error state, so a failing review read leaves the rest of the page up.
  The review card adds the week's news-impact study (`news_impact`, beyond the mockup; F6.2 says the director reads it).
  The cumulative lines use B7's shared `LineChart`. Only trades of status `settled` count (as B2's scoreboard counts
  them): a head-to-head trade that never entered (`no_entry`, `skipped_price_above_amount`; no profit) is no side of a
  match, no company trade and no point of a line; its match row says it did not enter and why.
- Paper portfolios: the add-trade form posts to `POST /api/v1/markets/{market}/paper-trades` from the same origin with
  `Content-Type: application/json`, the body fields of B13's route only (ticker, side, quantity, trade_date,
  price_basis, price only for a typed price, note when given) and an `Idempotency-Key` (`web-<uuid>`, within the tool
  layer's `^[A-Za-z0-9_-]{8,64}$`) created once per opened form and kept while the same request is sent again (after
  a 429, 503, no answer or a refusal); a changed request gets a new key. 202 and 200 close the form and show the
  request as Pending (this visit only: it shows in the portfolio once the next run imports it); 429 and 503 say try
  again later; other statuses show the tool layer's message. The form checks only what it can (an active company,
  shares above zero and whole in India, a session date, a typed price for the manual basis, a note of at most 200
  characters); the tool layer and WS4's import decide. The intraday check uses B7's shared `TradeCheckStatus`.
- Track record: the weekly series (B13's top-level `weekly`, beyond the mockup) fills the "Accuracy over time" card
  for the selected basis key only (the mockup's empty state was the open data request B13 has answered).

Differences from the mockups, each on purpose:
- The luck verdict uses the Strategy lab's three words on every page (`edge` only when the corrected interval lies
  above zero, `loss` when wholly below, else `luck?`); the Rule vs AI and Paper portfolios mockups called any interval
  that excludes zero an edge, a loss included. With fewer than 20 trades an edge reads `edge? too few` (07's wording).
- A your-cost figure that is not stored shows as "not stored"; the 06 mockup put the market figure in its place.
- The topbar title and the company search are B7's shell.
