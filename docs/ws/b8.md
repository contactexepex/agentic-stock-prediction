## Scope

about the stored data:
- in the chat panel of every page;

- through Slack `/ask`;

spend shown; there is no money budget in code (owner decision 2026-10-08).

    budget;

## Contract

**The explain tool** (`mcp/tools.yaml` `explain`, kind `read_ai`). It runs inside B5's policy point, `executor.ts`.
Identity, channel, the agent's kill switch, the arguments and the agent's read budget (a count, not money) are checked
there before the assistant is called. The arguments are `question` (at most 500 characters), `ticker?`, `strategy_id?`
and `conversation_id?`.

The assistant then does this, in order (`explainer.ts`):
1. **Kill switch.** It reads the newest `inbox.controls` row of agent `assistant` and of `*`. The assistant checks it
   itself as well, so an `explain` call from the Claude app (agent `claude-app`) is stopped too: `refused`,
   `kill_switch`.
2. **API key.** Without `ANTHROPIC_API_KEY` the call is `failed` ("not set up yet") and nothing is logged.
3. **Conversation.**
   - An explicit `conversation_id` continues that conversation only if it is a conversation's first question, asked
     by the same actor in the same market. Anything else, a later question's id included, starts a new one.
   - Without an id, Slack `/ask` continues the asker's latest conversation in the market if its last question is less
     than 30 minutes old (`SLACK_CONVERSATION_MINUTES`).
   - Without an id, the dashboard and the Claude app start a new conversation.
   - A conversation's id is the id of its first question.
4. **Log the question** (`app.assistant_questions`). A question that asks for advice or a real trade (`guard.ts`,
   e.g. "Should I buy NVDA tomorrow with real money?") is declined without a model call, at a cost of $0.
5. **Purge.** Questions and answers asked more than 90 days before now are deleted (best effort, on every question).
6. **The model loop.** Model `claude-sonnet-5-5` (F11 names Sonnet; `tools.yaml` `budget: {model: sonnet}`).
   - **Settings:** effort `low`, adaptive thinking (the model's default), non-streaming, `max_tokens` 1500.
   - **Cached prefix:** the fixed system prompt carries `cache_control`, and the tools are the six read tools of
     `mcp/agents/assistant.yaml` in a fixed order, so the prefix is the same for every question.
   - **Structured output:** `{text, cited[{id, kind}], not_in_data, declined}`.
   - **Refusal fallback (owner decision 2026-10-08).** Beta `server-side-fallback-2026-06-01` with `fallbacks: [{model:
     "claude-sonnet-5"}]`. It is pinned with the array form rather than `"default"`, so its price is known: Claude Sonnet
     5 is the model `"default"` sends Sonnet 5.5's `cyber` and `frontier_llm` declines to (claude-api skill), at the same
     $2 / $10. The orchestrator approved the pinning on 2026-10-08.
   - **History.** The question carries the last 4 finished turns of its conversation (`HISTORY_TURNS`) as plain text.
     Each earlier question is quoted, and each earlier answer is cut to 1,000 characters (`HISTORY_ANSWER_CHARS`). So
     the history adds at most 4 × (500 + 1,000) = 6,000 characters of quoted text, plus about 80 characters of framing
     per turn (about 6,400 characters in all). The model is told that earlier
     numbers are not evidence and must be read again.
   - **Limits.** At most 4 model calls per question; the last one has `tool_choice: none`. At most 6 tool calls in
     all. Counted from the question's arrival (before its log statements), no model call starts and no read runs
     after 25 s (`DEADLINE_MS`), and each call has 20 s with no retry (`CALL_TIMEOUT_MS`). So the model work ends within
     45 s of arrival. The closing statements follow: the answer and the spend, each under B5's 5 s statement timeout,
     and the tool layer's command-log row. They normally take well under a second. A log slower than the remaining
     time can still be cut off by the route's 60 s `maxDuration`; the question then stays "pending" ("no answer
     logged") and is not retried.
   - **Tools.** The model may name only the six read tools (`READ_TOOLS`). Any other name (a write tool, `explain`
     itself) gets `Not read: ... is not one of the assistant's read tools` and is not executed.
     - A read tool goes through `read(tool, args)`, B5's hook. That is `ToolLayer.execute` with the caller's own
       context, limited by B5 to tools of kind `read` that the caller's agent lists. So each read is gated, logged in
       `inbox.command_log` and counted in the caller's agent's read budget: `assistant` for the dashboard and Slack
       `/ask`, `claude-app` for the Claude app.
     - The request's market overrides any market the model passes.
     - A refused read returns `Not read: <reason>` to the model as an error result.
   - **Tool results** are cut at 16,000 characters and marked `[cut]`.
7. **Checks on the answer** (`guard.ts`):
   - An answer the model declined as advice, or whose text reads as advice, is replaced by the fixed decline.
   - Each cited id must occur as a whole JSON string value, not as a key, in what the model saw of the tool results
     after the cut. Other ids are dropped, and the text says so.
   - An answer that is not "not in the data" and keeps no citation is replaced by "Not in the data: the answer could
     not be tied to a stored record, so it is not shown."
   - A `refusal` stop (after the fallback) is a decline (`declined: refused`).
   - An API error is `failed`, in plain words (no driver or key text).
8. **Log the answer** in `app.assistant_answers`, with its tokens and real cost.
   - Each attempt in `usage.iterations` (the declined one and the fallback's) is charged at its own model's price:
     `claude-sonnet-5-5` and `claude-sonnet-5` at input $2, 5-minute cache write $2.50, cache read $0.20 and output
     $10 per million tokens (the claude-api skill's price table, cached 2026-10-06).
   - Any other model is charged at the dearest listed price (input $10, cache write $12.50, cache read $1, output
     $50), so nothing is under-counted.
   - The logged model is the one that served the answer.
   - A call that ended without an API answer (a timeout, a lost connection) has no usage to log; the Anthropic console
     shows what it billed.

**No money budget in code** (owner decision 2026-10-08, confirmed by the orchestrator with the owner at about 15:00Z).
This supersedes F11's "a code-side daily budget (about $0.65 per day)" and the $20 monthly cap in code:
- there is no reservation, no daily cap and no monthly cap;
- the Anthropic console's workspace spend limit is the only money limit;
- the assistant never answers `budget_exceeded` for money.

`budget_exceeded` still comes from B5's per-agent day count of reads (`mcp/agents/assistant.yaml`, 500). B5 logs it but
does not report it to #market-brief for assistant questions (fdb6b82 and 31e1d8d, judged in 87bb89e).

The tool's `data` is `{answer, spend, logged}`.
- `answer` is the catalogue's `assistant_answer`: `id` (`ask-<market>-<date>-<10 hex>`), `market`, `channel`,
  `asked_at`, `question`, `text`, `cited_ids`, `cited[]`, `as_of` (= `asked_at`, as the catalogue defines it),
  `not_in_data` and `declined`. B8 adds:
  - `cited[].source`: the read model and page key where the id was found;
  - `cited[].as_of`: that read model's as-of time;
  - `status`: `answered | not_in_data | declined | stopped | failed | pending`;
  - `sources[]`: every read-model lookup, with `found` and `as_of`;
  - `cost_usd`;
  - `conversation_id`;
  - `history_turns`: how many earlier turns the answer was given.
- `spend`: see below.

**`/api/assistant`** is served by the app project only. The gateway's middleware answers 404, and the handler checks
`MB_GATEWAY` too. Identity is `dashboardContext("assistant")`, never taken from the body.
- **`POST`** with `{market, question, ticker?, strategy_id?, conversation_id?}`.
  - The body must be `application/json`, at most 4,096 bytes, and its `Origin` (when sent) the app's own.
  - The answer is `{result, refusal_code, message, command_id, answer, spend, limits}`.
  - Statuses: 200 accepted; 422 validation_failed (e.g. a malformed `conversation_id`); 429 budget_exceeded (the read
    count); 503 kill_switch or failed; 403 other refusals; 400, 413, 415 a bad body, too large, not JSON.
- **`GET ?market=india|us`** returns `{market, answers, spend, limits, read_at}`.
  - `answers`: the market's, asked in the last 90 days, from every channel, without the actor. The newest 100,
    returned oldest first.
  - A 503 when the log cannot be read.
- **`spend`:** `{day: {spent_usd, starts_at}, month: {spent_usd, starts_at}, enabled}`. Days and months are UTC. The
  spend is the sum of the logged answers' real costs, both markets together. `enabled` is false when the kill switch is
  off.
- **`limits`:** `{question_max: 500, history_turns: 4, retention_days: 90}`.

**Page 11 and the chat panel** (`web/app/(cockpit)/[market]/assistant/_parts/`, mockup `design/mockups/11-assistant/`):

  - Page head: the status block of `GET /api/v1/markets/{market}/status`, through B7's `PageHead`.
  - "Ask the data" card: the conversation, oldest first. Each answer shows its state in words and an icon (answered

  - Beside the card: "How it answers", "Records cited" and "Spend" (today and this month, no cap, "switched off" when
    the kill switch is off). The mockup's Budget card becomes Spend after the owner's decision.
- **The panel.**

  - Closed, it renders nothing, so B7's slot stays `:empty` and hidden.
  - Open, it shows the current conversation, the composer, the spend line, "New", "Full page" and Close (Escape
    closes it too), with focus in the question box.
  - It sends the page in view as hints: the ticker of a company or stock-strategies page, and the strategy of
