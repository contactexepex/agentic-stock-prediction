# B8: Assistant

## Scope
Wave 4, session B8 (docs/SPEC.md F11 and section 10), branch `build/b8-assistant`. The assistant answers questions
about the stored data, in the chat panel of every page, on page 11 and through Slack `/ask`. It reads only through
B5's read tools, cites what it used, never advises, and runs under a server-side budget of $0.65 a day and $20 a
month. Batch 1 (this file so far) is the backend: the `explain` tool, the budget, the conversation log in MotherDuck
schema `app` and `/api/assistant`. Batch 2 is page 11 and the chat panel in B7's shell, and batch 3 the `/ask`
wiring once B5 has taken the requests below. Research only: nothing here writes outside the conversation log.

## Contract

**The explain tool** (`mcp/tools.yaml` `explain`, kind `read_ai`). It runs inside B5's policy point: identity, channel,
the agent's kill switch, arguments (`question` at most 500 characters) and the read budget are checked by
`web/lib/tools/executor.ts` before the assistant is called. The assistant then does this, in order
(`explainer.ts`):
1. **Kill switch.** The newest `inbox.controls` row of agent `assistant` and of `*`. The assistant checks it itself
   as well, so an `explain` call from the Claude app (agent `claude-app`) is stopped too: `refused`, `kill_switch`.
2. **API key.** Without `ANTHROPIC_API_KEY` the call is `failed` ("not set up yet") and nothing is reserved.
3. **Advice question.** A question that asks for advice or a real trade (`guard.ts`, e.g. "Should I buy NVDA tomorrow
   with real money?") is declined without a model call. It is logged at a cost of $0.
4. **Reservation.** The question's cost is reserved: `QUESTION_USD` = $0.10. One `INSERT ... SELECT ... WHERE` refuses
   it when the day's spend (UTC day) or the month's spend (UTC month) plus the reservation would pass $0.65 or $20.
   Spend is each question's real cost once answered, else its reservation, so a question that never finished still
   counts. Over budget: `refused`, `budget_exceeded`, with the budget line in the message; no model call.
5. **Purge.** Questions and answers asked more than 90 days before now are deleted (best effort, every question).
6. **The model loop.** Model `claude-sonnet-5-5` (F11 names Sonnet, `tools.yaml` `budget.model: sonnet`). Effort
   `low`, adaptive thinking (the model's default), non-streaming, `max_tokens` 1500. The fixed system prompt carries
   `cache_control`, and the tools are the six read tools of `mcp/agents/assistant.yaml` in a fixed order, so the
   prefix is identical for every question. Structured output: `{text, cited[{id, kind}], not_in_data, declined}`.
   - At most 4 model calls per question; the last one has `tool_choice: none`. At most 6 tool calls in all.
   - Before every call, its cost ceiling is checked: every input byte counted as half a token at the cache-write
     price, plus 1,000 tokens, plus the full 1,500 output tokens. If the cost so far plus that ceiling would pass
     $0.10, the question stops ("Stopped before an answer ..."). So a question's real cost stays within its
     reservation unless the API counts more than half a token per byte.
   - Each tool call goes through `read(tool, args)`, which is `ToolLayer.execute` with the caller's own context. So it
     is gated, logged in `inbox.command_log` and counted in the read budget. The request's market overrides any
     market the model passes. A refused call (for example a write tool named by text in the data) returns
     `Not read: <reason>` to the model as an error result.
   - A tool result is cut at 16,000 characters and marked `[cut]`.
7. **Checks on the answer** (`guard.ts`):
   - An answer the model declined as advice, or whose text reads as advice, is replaced by the fixed decline.
   - Each cited id must occur as a whole JSON string value in what the model saw of the tool results (after the cut).
     Others are dropped, and the text says so.
   - An answer that is not "not in the data" and keeps no citation is replaced by "Not in the data: the answer could
     not be tied to a stored record, so it is not shown."
   - A `refusal` stop is a decline (`declined: refused`). An API error is `failed` with plain words (no driver or key
     text).
8. **Log.** The answer and its real cost go to `app.assistant_answers`. The cost is computed from `usage`: input $2,
   5-minute cache write $2.50, cache read $0.20, output $10 per million tokens (the claude-api skill's price table,
   cached 2026-10-06).

The tool's `data`: `{answer, budget, logged}`.
- `answer` is the catalogue's `assistant_answer`: `id` (`ask-<market>-<date>-<10 hex>`), `market`, `channel`,
  `asked_at`, `question`, `text`, `cited_ids`, `cited[]`, `as_of` (= `asked_at`, as the catalogue defines it),
  `not_in_data`, `declined`. B8 adds:
  - `cited[].source`: the read model and page key where the id was found;
  - `cited[].as_of`: that read model's as-of time;
  - `status`: `answered | not_in_data | declined | stopped | failed | pending`;
  - `sources[]`: every read-model lookup, with `found` and `as_of`;
  - `cost_usd`.
- `budget`: see below.

**`/api/assistant`** (the app project only; the gateway's middleware answers 404, and the handler checks
`MB_GATEWAY` too). Identity is `dashboardContext("assistant")`, never from the body.
- `POST` with `{market, question, ticker?, strategy_id?}`. The body must be `application/json`, at most 4,096 bytes,
  and its `Origin` (when sent) the app's own. The answer: `{result, refusal_code, message, command_id, answer, budget,
  limits}`. Statuses:
  - 200: accepted;
  - 422: validation_failed;
  - 429: budget_exceeded;
  - 503: kill_switch or failed;
  - 403: other refusals;
  - 400, 413, 415: a bad body, too large, not JSON.
- `GET ?market=india|us` returns `{market, answers, budget, limits, read_at}`. The answers are the market's, asked in
  the last 90 days, the newest 100, oldest first, from every channel, without the actor. A 503 when the log cannot be
  read.
- `budget`: `{day: {spent_usd, budget_usd, left_usd, starts_at}, month: {the same}, question_usd, over_budget,
  enabled}`. `over_budget` is true when less than one question's reservation is left in the day or the month. This
  answers the design track's data request (design/README.md).
- `limits`: `{question_max: 500, daily_usd: 0.65, monthly_usd: 20, question_usd: 0.1, retention_days: 90}`. The
  numbers come from `mcp/tools.yaml` where it has them, the same as `design/mockups/_shared/shell.js`.

**Conversation log** (`web/lib/assistant/app.sql`). MotherDuck database `market_brief_inbox`, schema `app`, written
with `MOTHERDUCK_INBOX_TOKEN`: that is the web tier's only writable database (`market_brief` is read-only for
Vercel). Tables:
- `app.assistant_questions`, one row per question with its reservation;
- `app.assistant_answers`, one row per finished question with its tokens, calls and real cost.

An operational log, never imported into `data/`. The web tier deletes rows older than 90 days.

**For B5** (Slack `/ask`, `/mcp`), from `web/lib/assistant/index.ts`:
- `withAssistant(layer)`: the tool layer with the assistant as its explainer;
- `formatSlackAnswer(outcome)`: an ephemeral Slack body, every stored and model text escaped with `slackEscape`;
- `ASK_USAGE` and `ASK_WORKING`.

The hook B5's `ToolDeps.explainer` should have is `Explainer` in `web/lib/assistant/types.ts`.

**No change** to `api/openapi.yaml`: `/api/assistant` is outside `/api/v1`, and design/README.md lists it as page 11's
endpoint.

## Open questions
Each with the default B8 took.

1. **Requests to B5**, sent 2026-10-08:
   1. the `@anthropic-ai/sdk` 0.128.0 dependency;
   2. `api.anthropic.com` in the host allowlist;
   3. the `ToolDeps.explainer` hook in the executor;
   4. Slack `/ask` through `withAssistant`, with `maxDuration` 60, and `/mcp` through the same.

   Until 1 lands, B8 cannot merge to main (CI has no SDK). Until 3 lands, `explain` answers B5's "coming soon" in every
   channel.
2. **Where schema `app` lives.** In `market_brief_inbox`, with the inbox token, because Vercel has no write access to
   `market_brief`. Default: as built. The owner runs `web/lib/assistant/app.sql` there once (Owner setup).
3. **Refusal fallbacks are off.** The claude-api guidance turns on server-side `fallbacks` for Sonnet 5.5 by default.
   B8 leaves them off: a fallback can re-run the request on a dearer model, which breaks the $0.10 ceiling per
   question that the hard budget relies on. A refusal is shown as "The model declined to answer this question."
   Default: off. The owner may choose on.
4. **One question, one answer.** The panel shows the conversation, but each question is answered on its own, without
   the earlier turns. This keeps each question's cost bounded and every answer self-contained. Default: as built.
5. **Every refused question is reported to the owner in #market-brief.** This is B5's executor rule for refusals, and
   it includes `budget_exceeded`. Default: kept.
6. **The answer's `as_of`.** It is the time asked, as the catalogue defines it. The data's own as-of times are in
   `cited[].as_of` and `sources[].as_of`. Default: as built.
